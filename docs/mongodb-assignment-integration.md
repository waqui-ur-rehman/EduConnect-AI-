# Phase 3 Step 3: assignments

The existing Course Assignments tabs call authenticated `/api/assignments` endpoints for MongoDB courses. Teacher course ownership and student enrollment are checked on every server operation. Students see only published assignments for an approved course. A submission is unique per assignment and student; resubmission replaces ungraded work before the due date. The server rejects resubmission after grading and all submissions after the due date. Grades and feedback are stored on the submission and returned only to that student and the owning teacher.

Teacher and student files are private. Uploads accept PDF, TXT, PNG, JPG, and DOCX, at most 10 MB, with extension, MIME type, and content checks. Download checks the authenticated course and the specific assignment or submission reference. Files are stored under backend/uploads/content using UUID names.

When the teacher opens Course Assignments in the same browser where old records were made, existing browser assignments are imported by the course's MongoDB or legacy ID. The original browser records remain in localStorage and receive a `mongoAssignmentId` marker. MongoDB has a unique index on teacher, course, and legacy assignment ID so retrying cannot create duplicates. Existing browser submissions and their IndexedDB attachments remain local. They cannot be treated as authenticated, server-graded work without student ownership proof; they are not silently imported. If an old assignment referenced an attachment, restore it by editing the imported draft and uploading the file from the original browser. Imported assignments publish only if the course has an approved published version.

Verification: `backend/tests/assignmentWorkflow.test.mjs` uses HTTP and a uniquely named disposable MongoDB database to check ownership, publication, enrollment, resubmission, grading, student feedback, and private attachments. The whole backend suite, scoped ESLint, and frontend build were also run. A live user-session walkthrough requires logging into the running app in the original browser and restarting the backend after these changes. No real user assignment or submission was inserted by the tests.
